# M0 — Foundations

## T001 — Repository scaffold and CI

**Goal:** an empty but buildable Cargo workspace with all crates and CI.
**Depends on:** nothing.
**Scope:** repository root, all crate directories.

**Requirements**
- Cargo workspace with the crates listed in ARCHITECTURE §2, each with a minimal `lib.rs` or
  `main.rs`, `#![forbid(unsafe_code)]`, and shared metadata (`license = "Apache-2.0"`,
  edition, version `0.1.0`) via `[workspace.package]`. Shared dependency versions via
  `[workspace.dependencies]`.
- `LICENSE` (Apache-2.0 full text), `rust-toolchain.toml` (stable), `rustfmt.toml`,
  `.gitignore`/ignore file for `target/`.
- CI workflow running fmt check, clippy with `-D warnings`, and tests on Linux, Windows, macOS.
- `lode --version` and `loded --version` print the workspace version.

**Acceptance**
- `cargo build --workspace` and `cargo test --workspace` succeed on a clean checkout.
- CI configuration is present and runs the three checks on three platforms (manual: first run).

**Out of scope:** any real functionality.

## T002 — Core types (`lode-core`)

**Goal:** the pure data layer every other crate builds on.
**Depends on:** T001.
**Scope:** `lode-core`.

**Requirements**
- `ObjectId`: 32 bytes; hex parse/format; serde as hex string; `Ord`, `Hash`.
- `blob_id(reader)` streaming BLAKE3; `tree_id(bytes)` using derive-key context
  `"lode 2026 tree v1"` (ARCHITECTURE §3.1).
- `DepotPath`: validated, NFC-normalized path type implementing every rule in SPEC §5.7;
  `segments()`, `parent()`, `join()`, case-fold key for collision checks. Parsing returns a
  typed error naming the violated rule.
- `Tree`, `TreeEntry`, `EntryKind`, flags; canonical `encode`/`decode` exactly per
  ARCHITECTURE §3.2, rejecting every non-canonical form.
- `ObjectHeader` encode/decode per ARCHITECTURE §3.3.
- Change types shared by commit and shelf: `Change { path, action, base_id, new_id, kind,
  executable, size, copy_from }`, plus validation of a change set (duplicates, a path that is
  both file and directory prefix, case-insensitive collisions within the set).
- `ErrorCode` enum with the stable codes of ARCHITECTURE §6 and their string forms.
- Glob matching helper over `DepotPath` (wrapping `globset`) and `.lodeconfig` parsing
  (SPEC §5.6) with unknown keys ignored.
- No I/O beyond `std::io::Read` in the hashing helper. No async.

**Acceptance**
- Property test: `decode(encode(tree)) == tree` for arbitrary valid trees; encoding is
  byte-identical regardless of insertion order.
- Decode rejects: unsorted entries, duplicates, trailing bytes, over-long varints, unknown kind,
  non-zero reserved flag bits, invalid names.
- Table-driven tests for every path rule in SPEC §5.7, including Windows reserved names
  (`CON`, `NUL`, `COM1`, with and without extension) and NFC normalization.
- `blob_id` of the empty input and of a known vector match the published BLAKE3 test vectors.
- Tree id differs from blob id for identical bytes.

**Out of scope:** storage, networking, tree mutation against a store (T014).

## T003 — Blob store (`lode-store`)

**Goal:** durable, verified, content-addressed object storage on a filesystem.
**Depends on:** T002.
**Scope:** `lode-store`.

**Requirements**
- `BlobStore` trait and `FsBlobStore` per ARCHITECTURE §3.4, including layout, temp files,
  fsync, and the no-replace publish on all three platforms. The platform call for no-replace
  publish may use `unsafe` or a small crate if std cannot express it; isolate and justify.
- `put` streams: hash raw bytes, compress with zstd level 3, fall back to codec `none` when
  the saving is under 3 % (decide after the first 1 MiB to avoid double work on large
  incompressible files; document the heuristic).
- `put` accepts an optional expected raw length and fails `too_large` beyond a configured cap.
- `get` returns kind, raw length and an `AsyncRead` of raw bytes; enforces raw length while
  decompressing; a corrupt header or truncated payload is a typed error.
- `get_stored` returns the stored (possibly compressed) stream and codec, for serving
  `Accept-Encoding: zstd` without recompression.
- `list` yields ids with modification time, tolerating stray files in the tree.
- Stale files in `tmp/` older than 24 h are removed on open.

**Acceptance**
- Round-trip of empty, small, multi-megabyte compressible and incompressible content.
- `put` with a wrong `expect` returns `hash_mismatch` and leaves no file behind.
- Two concurrent `put`s of the same content: one `Created`, one `AlreadyPresent`, one file.
- An existing object is never modified by a later `put` (compare bytes and mtime).
- A blob whose header claims a smaller raw length than its payload expands to is rejected.
- Memory stays bounded when storing a 1 GiB stream (test with a generated reader; assert via
  a counting allocator or by construction with a small fixed buffer — state which).

**Out of scope:** S3 backend, chunking, GC logic (T018).

## T004 — Metadata store (`lode-meta`)

**Goal:** the SQLite layer with schema, migrations and transaction primitives.
**Depends on:** T002.
**Scope:** `lode-meta`.

**Requirements**
- Open/create `meta.db` in WAL mode with `foreign_keys=ON`, `synchronous=FULL`,
  a busy timeout, one writer connection and a read pool; async wrappers via `spawn_blocking`.
- Migration runner: embedded, numbered, transactional; `schema_version`; refuses unknown newer
  versions; accepts additional migration sets registered by modules (namespaced by module name).
- Core schema exactly per ARCHITECTURE §4.2, with the stated index.
- `ReadTx` and `WriteTx` types. Typed row structs and query methods for depots, principals,
  groups, tokens, ACL rows, branches, revisions, changes, merges, `rev_meta`, outbox and
  cursors. Only what M1 needs; later tasks add methods.
- Branch-ancestry resolution (ARCHITECTURE §4.3) and a path-history query built on it.
- Online backup helper using SQLite's backup API.

**Acceptance**
- Fresh database migrates to the latest version; reopening is a no-op; a database with a higher
  version fails to open with a clear error.
- A module migration set applies once and is tracked separately.
- A `WriteTx` dropped without commit leaves no trace.
- Path-history query returns the right revisions across a three-level branch chain, and does
  not return parent-branch revisions newer than the branch point.
- Concurrent readers proceed while a write transaction is open.

**Out of scope:** business rules (permissions evaluation, commit logic).

## T005 — API types (`lode-proto`)

**Goal:** one definition of every request and response, shared by server and client.
**Depends on:** T002.
**Scope:** `lode-proto`.

**Requirements**
- Serde types for every endpoint in ARCHITECTURE §6 and module endpoints in §9.1–9.2,
  including the commit request (§5.1), manifest lines, revision and change views, the error
  body, and `/info`.
- Field names in `snake_case`; ids as hex strings; times as RFC 3339 UTC; unknown fields
  ignored on input; optional fields omitted on output when empty.
- Constants for paths, header names, limits and the API version.

**Acceptance**
- Snapshot tests (`insta`) of the JSON form of each type, so accidental wire changes fail CI.
- The commit example in ARCHITECTURE §5.1 deserializes and re-serializes equivalently.

**Out of scope:** HTTP handling.
