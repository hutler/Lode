# M14 — Server admin web UI

`loded` serves a small web UI for server administrators: everything `lode admin` does today,
in a browser, plus an overview of the server's health. Asked for by the person on 2026-11-14
("we can make webui for server for admin").

Ground rules for every task in this milestone:

- Served by `loded` itself at `/admin/` on the same listener and TLS as the API; nothing to
  install. `[admin_ui] enabled = true` by default; `false` turns it off (404).
- Server-rendered HTML from Rust, with a small escaping helper in `lode-server` (every value
  is escaped; no template crate, no JavaScript build, no Node.js). Pages work without
  JavaScript; a few lines of plain JS (embedded, under a strict CSP with no inline script)
  add confirmations and live refresh. One embedded stylesheet that follows the system light
  or dark theme and works on a phone.
- Only server administrators get in. Others who sign in see "This account is not a server
  administrator". Everything a page does goes through the same code as the API handlers, so
  permissions, validation and errors are the same.
- Sessions: sign-in with password or single sign-on (T122) issues a session cookie
  (`HttpOnly`, `SameSite=Strict`, `Secure` with TLS, 8 hours, ended on sign-out or when the
  user is disabled), backed by an ordinary token with the `admin` scope named "web admin".
  Every form carries a CSRF token. Sign-in attempts share the API's rate limit.
- Pages are tested with handler tests that parse the HTML, and screenshotted with Playwright
  (light, dark, phone width) for visual review.

## T140 — Sessions, layout and overview

**Goal:** an administrator signs in and sees how the server is doing.
**Depends on:** T122.
**Scope:** `lode-server`, `loded`, docs.

**Requirements**
- `/admin/sign-in` (password, and "Sign in with …" when SSO is on), `/admin/sign-out`.
- Layout: top bar with server name and version, navigation (Overview, Depots, People, Access,
  Webhooks when the module is on, Settings), signed-in user.
- Overview: version, uptime, listen address, TLS mode and certificate expiry, storage kind
  (files or S3) and size, database size, number of depots, users, agents and active tokens,
  last scheduled backup (time, result, size) and next one, last GC and fsck per depot, enabled
  modules, recent commits across depots.
- `[admin_ui]` in `loded.toml` and the commented default.

**Acceptance**
- Tests: sign-in and sign-out, a non-admin refused, a disabled user's session ends, CSRF
  token required on every POST, session cookie flags with and without TLS, every value
  escaped (a depot named `<script>` shows as text), `enabled = false` gives 404.
- Screenshots of sign-in and overview.

**Out of scope:** pages of T141–T143.

## T141 — Depots and maintenance

**Goal:** manage depots from the browser.
**Depends on:** T140.
**Scope:** `lode-server`.

**Requirements**
- Depot list (revisions, branches, size, last commit) and create.
- Depot page: branches (with archived ones), recent revisions, locks (with break lock for
  admins, when the locks module is on), GC (dry run shows what would go, then run), fsck (and
  full), obliterate (paths, reason, dry run listing every use, then confirm) and the
  obliterated list.

**Acceptance**
- Tests for each action, including an obliterate refused while a head holds the content and a
  GC dry run that changes nothing.
- Screenshots of the depot list, a depot, a GC report and an obliterate dry run.

**Out of scope:** browsing file contents.

---

## T142 — People, tokens and access rules

**Goal:** manage who can do what from the browser.
**Depends on:** T140.
**Scope:** `lode-server`.

**Requirements**
- Users: list, create (password or SSO identity), disable and enable, set password, link or
  unlink SSO. Agents: list, create with owner, disable. Groups: create, add and remove members.
- Tokens: list per principal (never values), revoke, create (value shown once, with copy).
- Access rules: list in evaluation order, add, remove, and "check access" for a principal and
  path, showing which rule decided.

**Acceptance**
- Tests for each action and for the token value appearing once only.
- Screenshots of users, a user, tokens and access rules with a check result.

**Out of scope:** group sync from the identity provider.

---

## T143 — Webhooks, settings and the guide

**Goal:** finish the admin UI and document it.
**Depends on:** T141, T142.
**Scope:** `lode-server`, docs.

**Requirements**
- Webhooks (when enabled): list per depot, add, remove, ping, deliveries with status.
- Settings: the effective `loded.toml` as the server read it, secrets shown as `***`.
- User guide chapter "Admin web UI" with screenshots; SPEC and ARCHITECTURE sections;
  security checklist entries (put it behind TLS, turn it off if unused).

**Acceptance**
- Tests for webhooks actions and that no secret appears in the settings page.
- Screenshots of webhooks and settings; PDF regenerated.

**Out of scope:** a public (non-admin) web UI for browsing depots.
