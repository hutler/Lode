# M13 — Lode Desk on Slint

Lode Desk moves from Tauri (a web view with React) to Slint, so it is a native Rust program:
no web view, no Node.js, one `cargo build`, Windows 11 style controls on Windows and the
platform's look elsewhere. Decided by the person on 2026-11-14 ("Slint (Rust, native look)").
Everything a user can do in the app today (M9–M11) stays; only the screens are rebuilt.
`lode-ops` does not change: the app keeps calling the same operations as `lode`.

Ground rules for every task in this milestone:

- `crates/lode-desk` stays its own Cargo workspace. Its `rust-version` becomes 1.92, which
  Slint 1.18 needs; the main workspace stays on 1.88.
- Slint is used under its Royalty-free License 2.0 (allowed for desktop apps; the GPL option
  would not fit Apache-2.0). The About dialog shows the "Made with Slint" notice the licence
  asks for, and `THIRD-PARTY.md` names the licence. Justify the dependency in the status row.
- Style `fluent` on Windows, `cupertino` on macOS, `fluent` on Linux (Slint's `native` style
  needs Qt, which we do not ship); light or dark follows the system.
- Operations never run on the UI thread. A worker runs one `lode-ops` operation at a time per
  workspace and reports progress events back with `slint::invoke_from_event_loop`.
- The Rust side of the Tauri app (`desk.rs`, `watch.rs`, `links.rs`, `update.rs`) is reused as
  the app's backend; Tauri types are removed from it. Screens are `.slint` files under
  `crates/lode-desk/ui/`, compiled by `slint-build`.
- UI tests use Slint's testing backend (`i-slint-backend-testing`): find elements by
  accessible label, click, type, and check what is shown, headless. Screenshots are rendered
  with the software renderer into PNG files for visual review, light and dark.
- Each task removes the React screens it replaces; T135 removes the rest of `ui/` and Tauri.

## T130 — Slint shell, sign-in, open and check out

**Goal:** the Slint app starts, signs in and opens or checks out a workspace.
**Depends on:** T116.
**Scope:** `lode-desk`.

**Requirements**
- `main` starts the Slint window (1280×800, minimum 900×560) titled "Lode Desk".
- Backend: the former Tauri commands become plain functions over `lode-ops`; a worker thread
  runs them and sends results and progress to the UI.
- Screens: welcome (recent workspaces, Open folder, Check out, Sign in), sign-in (server,
  name, password, and "Sign in with …" when `/info` offers single sign-on), check out
  (server, depot, branch, folder, progress), workspace tabs with the sidebar (branch,
  revision, server) and the error banner with the operation's message and advice.
- Native folder pickers through `rfd`.
- Keyboard: Tab order, Enter and Escape in dialogs, Ctrl+O, Ctrl+Shift+O (check out).
- Accessible labels on every control (they are also what the tests use).

**Acceptance**
- Testing-backend tests: sign-in (password, wrong password, SSO offered and not), check out
  with progress, open a workspace, error banner text and advice, against a test server.
- Screenshots of welcome, sign-in, check out and an open workspace, light and dark.
- Builds and starts on Linux in CI; manual start on the Windows PC.

**Out of scope:** the views of T131–T134.

## T131 — Pending changes, commit and changelists

**Goal:** daily work in the Slint app.
**Depends on:** T130.
**Scope:** `lode-desk`.

**Requirements**
- The changes view of T092 and T100: status grouped by changelist, check boxes, select all,
  file icons by kind, the commit box with message history, commit with progress, refresh on
  file changes through the existing watcher, revert with confirmation, changelists (create,
  move, rename, delete).
- Large lists stay smooth: the list model is virtual (`VecModel` behind a `ListView`), tested
  with 20 000 changed files.

**Acceptance**
- Testing-backend tests for pick, commit, refused commit (locks, conflicts), revert and every
  changelist action; a timing test that 20 000 rows load in under a second.
- Screenshots of the changes view, a refused commit and changelists.

**Out of scope:** diffs (T132).

## T135 — Links, installers, updates and the guide

**Goal:** ship the Slint app as T113–T115 shipped the Tauri one, and remove Tauri.
**Depends on:** T134.
**Scope:** `lode-desk`, release workflow, docs.

**Requirements**
- One instance only: a second start passes its `lode://` link to the first over a local
  socket and exits; `lode://` links work as in T113 (scheme registered by the installers).
- Installers with `cargo-packager`: MSI (WiX) and NSIS on Windows, `.deb` and AppImage on
  Linux, `.dmg` on macOS, with the same names and install paths as T114.
- Updates keep T114's feed and minisign signatures (same key, same `latest.json`), checked
  with `minisign-verify`; the settings that turn checks off stay.
- `ui/` (React), `package.json`, Tauri and its plugins are removed; CI builds without Node.js.
- The Lode Desk guide and its screenshots are redone from the Slint screenshots;
  `desk-acceptance.md` is updated for the manual check on the PC.

**Acceptance**
- Tests: link hand-over between two instances, signature check (good, wrong key, damaged),
  update settings; the release workflow builds every installer in CI.
- Manual on the PC: install the MSI, open a `lode://` link, update from a test feed.

**Out of scope:** code signing certificates (as in T114, the person provides them later).
