# M8 — Easy setup

A small team gets from nothing to a TLS-protected server and signed-in clients in about 15
minutes, with no reverse proxy and no hand-edited files, and turns an existing folder into a
depot with one command. Plan: "Lode after v1" (2026-11-14).

## T080 — Header timeouts

**Goal:** `loded` can face the internet without a reverse proxy.
**Depends on:** T054.
**Scope:** `lode-server`, `loded`, docs.

**Requirements**
- Request headers must arrive within `[connections] header_timeout_seconds` (default 30);
  slower connections are closed. The same limit closes an idle kept-alive connection (one
  setting rather than a separate idle timeout: hyper times the wait for the next request's
  headers the same way).
- A per-address limit on open connections (`[connections] max_per_address`, default 64; an
  IPv6 address counts by its /64 network).
- SPEC §10.1 and `docs/HARDENING.md` drop the "put it behind a proxy" requirement.

**Acceptance**
- A client that sends headers one byte per second is disconnected after the timeout.
- Connections past the per-IP limit are refused; others still connect.

**Out of scope:** rate limiting by account.

## T081 — Built-in TLS from Let's Encrypt

**Goal:** HTTPS with no proxy and no manual certificates.
**Depends on:** T080.
**Scope:** `loded`, docs.

**Requirements**
- `[tls] acme_domain = "lode.example.com"` and `acme_email` obtain and renew a certificate
  over TLS-ALPN-01 on the HTTPS port; certificates are cached in the data directory.
- `[tls] cert` / `key` still work and are exclusive with ACME.
- `acme_directory` can point at a staging or private ACME server.

**Acceptance**
- Against a local test ACME server (Pebble), `loded` obtains a certificate and serves HTTPS;
  a restart reuses the cached one.

**Out of scope:** DNS-01 challenges, wildcard certificates.

---

## T082 — `loded setup` and a native Windows service

**Goal:** first run without editing files.
**Depends on:** T081.
**Scope:** `loded`, `packaging/`, docs.

**Requirements**
- `loded setup` asks for the data directory, listen address, domain (or none for local use)
  and the admin password, writes a checked `loded.toml`, and runs `init`. Every answer can be
  given as a flag for scripted installs.
- `loded service install|uninstall|start|stop` registers `loded` as a Windows service itself
  (no WinSW wrapper); on Linux it writes the systemd unit.
- Scheduled backups: `[backup] every = "24h"`, `keep = 7`, into `[backup] dir`, using the
  existing `loded backup`.
- `docs/UPGRADING.md`: how to move from one release to the next.

**Acceptance**
- `loded setup` with flags produces a server that starts and accepts the chosen admin
  password.
- Service install and uninstall on Windows (manual), systemd unit content (test).
- A backup runs on schedule (clock-driven test) and old ones beyond `keep` are removed.

**Out of scope:** a web setup page.

## T083 — Server packages

**Goal:** install the server the native way on each platform.
**Depends on:** T082.
**Scope:** `packaging/`, release workflow.

**Requirements**
- Windows MSI (WiX) installing `loded` and `lode`, running `loded setup` and
  `loded service install`, with an uninstaller that keeps the data directory.
- `.deb` and `.rpm` that create a `lode` user, the data directory and the systemd unit.
- `packaging/compose.yaml` that runs the image with built-in TLS and a named volume.
- A one-line install script for Linux that picks the right package.

**Acceptance**
- Packages are built by the release workflow; install, start, and uninstall are checked in
  CI containers for deb and rpm, and manually for the MSI.

**Out of scope:** signing (decided: unsigned for 0.x).

## T084 — Client packages

**Goal:** install `lode` the native way and keep it current.
**Depends on:** T072.
**Scope:** `packaging/`, release workflow, `lode-cli`.

**Requirements**
- Windows MSI adding `lode` to PATH, and a `winget` manifest.
- A Homebrew tap formula for macOS and Linux; `.deb` and `.rpm`.
- `lode self-update` downloads the newest release for this platform, checks its SHA-256 from
  the release checksums, and replaces the binary; it refuses when installed by a package
  manager and says which command to use instead.

**Acceptance**
- `self-update` against a local test release server replaces the binary and refuses a bad
  checksum.

**Out of scope:** the GUI's own updater (M11).

## T085 — `lode init` and templates

**Goal:** an existing folder becomes a depot in one command.
**Depends on:** T053.
**Scope:** `lode-cli`, docs.

**Requirements**
- `lode init <server>/<depot> [--template T] [--dry-run]` in a folder with files: creates
  the depot (needs admin), writes `.lodeignore` and `.lodeconfig` from the template, turns
  the folder into its workspace, adds every file that is not ignored, and commits.
  `--dry-run` lists the file count and total size and changes nothing.
- Templates built into the binary: `generic`, `unreal`, `unity`, `godot`, `rust`, `node`.
  `unreal`, for example, ignores `Binaries/`, `Intermediate/`, `Saved/`,
  `DerivedDataCache/` and makes `*.uasset` and `*.umap` lock-required.
- An interrupted `init` can be rerun and finishes the same commit.

**Acceptance**
- `init` on a folder of 1,000 files commits exactly the non-ignored ones; a second workspace
  checks out the same tree.
- Each template's ignore and lock rules parse and match their sample paths.

**Out of scope:** templates from a URL.

## T086 — Git import

**Goal:** move an existing Git project to Lode with its history.
**Depends on:** T085.
**Scope:** new crate `lode-import`, `lode-cli`.

**Requirements**
- `lode import git <repo-path> --branch <b> <server>/<depot>` replays the branch's
  first-parent history as one Lode commit per Git commit, keeping author, date and message in
  the commit (as provenance, since the committer is the importing account).
- Resumable: a rerun continues after the last imported commit, recorded in the commit
  provenance.
- Git LFS pointers are replaced by their content when it is available locally.

**Acceptance**
- A 50-commit test repository with adds, edits, deletes, renames and binary files imports;
  every revision's tree matches the Git tree.
- An import stopped halfway resumes without duplicates.

**Out of scope:** Git merges other than first parent, SVN (later).

## T087 — Setup guide and acceptance

**Goal:** the 15-minute claim is true and documented.
**Depends on:** T080–T086.
**Scope:** docs, tests.

**Requirements**
- The user guide gets a "Quick start" for Windows, Linux VDS and Docker, using the packages,
  `loded setup`, `lode init` and `lode import git`.
- A scenario test: setup with flags, `init` with a template, a second client checks out.

**Acceptance**
- The scenario test passes; the quick start is followed once by hand on Windows and on a
  Linux VDS (manual).

**Out of scope:** the GUI.
