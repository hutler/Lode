# M10 — GUI team work

Lode Desk covers what a team does together every day: lock files before editing them, group
changes into changelists, shelve work for review and submit it, see checks on revisions and
shelves, and compare images. Plan: "Lode after v1" (2026-11-14). Everything goes through
`lode-ops`, so the app and `lode` agree on every rule and error.

## T100 — Locks

**Goal:** lock and unlock files without a terminal, and see who holds what.
**Depends on:** T094.
**Scope:** `lode-desk`.

**Requirements**
- A Locks section lists the branch's locks (path, owner, workspace, comment, when), with a
  filter for "mine" and a text filter on the path. It counts toward the sidebar badge.
- Lock and Unlock from the Changes view: in the details panel and the right-click menu, for one
  file or all picked files, with an optional comment. A file that needs a lock offers "Lock"
  first.
- A refused lock shows who holds each file (`locked`, `details.paths`) or says to update first
  (`out_of_date`). Breaking someone else's lock asks first and needs depot admin
  (`--force`); the button says so.
- A server without the locks module (`module_disabled`) shows the section as unavailable,
  not as an error.
- The Changes view and the Locks section refresh after every lock operation.

**Acceptance**
- Rust tests: lock, list and unlock through the app's commands against a test server,
  including a lock held by someone else.
- UI tests for locking picked files, the refusal naming the holder, and breaking a lock.
- Screenshots of the Locks section and a refused lock.

**Out of scope:** lock notifications from the server.

## T101 — Changelists

**Goal:** split pending changes into named groups and commit one group at a time.
**Depends on:** T094.
**Scope:** `lode-desk`.

**Requirements**
- Create, rename the description of, and delete changelists from the Changes view.
- Move files between changelists by drag and drop and with "Move to changelist" in the
  right-click menu (one file or all picked). Moving one half of a move takes the other along,
  as `lode changelist move` does.
- "Commit changelist" commits exactly that group (`commit -c`), with its description as the
  default message.

**Acceptance**
- Rust tests for new, move, commit of one changelist and delete.
- UI tests for drag and drop, the menu move and committing a changelist.

**Out of scope:** changelists shared between workspaces.

## T102 — Shelves and submit

**Goal:** shelve work, review shelves, and submit them, as the CLI and the editor plugin do.
**Depends on:** T101.
**Scope:** `lode-desk`.

**Requirements**
- Shelve the picked files or a changelist with a description; "keep my changes" leaves them
  in the workspace. Update an open shelf of mine with new changes.
- A Shelves section lists shelves (mine or everyone's, open, submitted or deleted) and shows a
  shelf's details: description, versions, changed files and each file's diff (T094 view).
- Unshelve into the workspace with the outcome per file (applied, merged, conflicted, …).
- Submit a shelf at the version shown; a shelf changed since is refused and says so. A submit
  refused by required checks (`checks_required`) lists each missing check and why.
- Delete my shelf, after asking.

**Acceptance**
- Rust tests for shelve, list, show, unshelve, submit and the stale-version refusal.
- UI tests for shelving picked files, the shelf view and the checks refusal.

**Out of scope:** comments on shelves.

## T103 — Check badges

**Goal:** see build and test results where people look at work.
**Depends on:** T093, T102.
**Scope:** `lode-desk`.

**Requirements**
- History rows and shelves show one badge for their checks: the worst state, with a count.
- The revision and shelf details list each check (name, state, summary, reporter, when) with
  its link opened in the system browser.
- Checks load only for the rows on screen, a page at a time, and refresh when a row comes
  back into view after a minute.
- A server without the checks module shows no badges and no error.

**Acceptance**
- UI tests for the badge's worst-state rule and for a server without checks.
- Rust test reading checks on a revision through the app's command.

**Out of scope:** reporting checks from the app.

## T104 — Image diff

**Goal:** compare images the way artists expect.
**Depends on:** T094.
**Scope:** `lode-desk`, `lode-ops` if reading a stored file to memory needs it.

**Requirements**
- PNG, JPEG, GIF, WebP and BMP files open an image diff instead of the binary note: side by
  side, swipe and onion skin, with each side's dimensions and size.
- Works for a working file against its base and for a file as a revision changed it.
- Images over 64 MB, or formats the web view cannot show, fall back to the binary note and say
  why.

**Acceptance**
- UI tests for the three modes and the fallback; screenshots of each mode.

**Out of scope:** texture formats (`.uasset`, `.dds`) and pixel-level difference maps.
