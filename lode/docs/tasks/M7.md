# M7 — Release v1

Get the work of M0–M6 onto `main`, onto GitHub and into a first tagged release (0.1.0), and
add the small command-line features editor integrations need (Lode for Unreal, SPEC of that
subproject, section 5, items 4, 7, 8 and 9). Nothing here changes the server.

Decided 2026-11-14 (post-v1 plan): the first release is 0.1.0; setup (M8) comes before the
desktop client (M9–M11).

## T070 — Release preparation

**Goal:** `main` holds v1, and CI proves it on Linux, Windows and macOS.
**Depends on:** T064.
**Scope:** repository layout, `Cargo.toml`, `.github/workflows/`, docs.

**Requirements**
- `main` is fast-forwarded to the end of the task-branch chain (`lode/T064-unattended`). The
  task branches stay as they are.
- `rust-version` in the workspace `Cargo.toml` states the real minimum: 1.88 (needed by
  `rmcp` 3.x). CI gains a job that builds the workspace with exactly that toolchain.
- CI runs fmt, clippy and the tests on `ubuntu-latest`, `windows-latest` and `macos-latest`,
  plus the container smoke test. Anything that fails only on macOS is fixed here.
- The repository README says what Lode is, how to install a release, and links the user
  guide.
- Pushing to GitHub needs a repository the owner creates; until then everything is done
  locally.

**Acceptance**
- `cargo +1.88 check --workspace --all-targets` passes.
- The CI workflow passes on all three systems (manual: the first run on GitHub).

**Out of scope:** signing, installers (M8).

## T071 — Command-line support for editor integrations

**Goal:** an editor plugin can query and act on many files with few, cheap calls.
**Depends on:** T028, T031.
**Scope:** `lode-cli`, `lode-workspace`, docs.

**Requirements**
- `lode status --unchanged [paths]` also lists tracked files that are unchanged, with status
  `unchanged`. Every file entry of `status --json` gains `lock_required` (the file matches
  the lock rules, whatever its state).
- `lode status --remote [paths]` adds `"remote": {"head_rev", "files": [...]}`: for each file
  in scope that has a newer version on the branch head (`"newer": true`, `"head_rev"` of the
  branch) or a lock held by anyone (`"locked_by": {"name", "kind"}`, `"lock_workspace"`, and
  `"mine": bool` for this workspace's own lock). Files with neither are left out. It costs
  one manifest delta and one lock listing, however many paths are named.
- `lode cat <path>[@rev] -o <file>` writes the content to `<file>` (temporary file plus
  rename, so a reader never sees half a file) instead of standard output, and with `--json`
  prints `{"path","rev","id","size","output"}`.
- `--paths-from <file>` (global; `-` reads standard input) adds the file's lines as path
  arguments: one path per line, UTF-8, an optional byte-order mark, `\r\n` or `\n`, blank
  lines skipped. Accepted by the commands that take a list of paths: `status`, `add`, `rm`,
  `revert`, `diff`, `commit`, `lock`, `unlock`, `shelve`, `changelist move`, `clean`. Any
  other command refuses it with a usage error.
- Paths may be absolute, with either slash. On Windows the comparison with the workspace
  root ignores letter case, as the file system does.

**Acceptance**
- `status --unchanged` on named paths reports state, changelist, `locked` and
  `lock_required` for each, including unchanged files.
- With a newer revision committed and a lock taken from a second workspace, `status --remote`
  reports both, from exactly one manifest request and one locks request (counted on the test
  server).
- `cat -o` writes a binary file byte for byte; nothing goes to standard output.
- `commit --paths-from` with 3 paths out of 5 changed files commits exactly those 3, also
  with `\r\n` lines, a byte-order mark and standard input.
- An absolute path with forward slashes is accepted; on Windows, one whose drive letter or
  folder names differ in case from the root is too (unit test).

**Out of scope:** a long-running server process for editors.

## T072 — First release

**Goal:** Lode 0.1.0 is downloadable.
**Depends on:** T070, T071, and the GitHub repository.
**Scope:** release workflow, docs.

**Requirements**
- Tag `lode-v0.1.0`; the release workflow publishes the five archives with checksums and the
  `loded` container image.
- The user guide and `docs/tasks/README.md` name the release; the PDF is regenerated.

**Acceptance (manual)**
- The archives download and run `lode --version` on Windows and Linux.
- `docker run` of the published image passes the container smoke test.

**Out of scope:** installers and package managers (M8).
