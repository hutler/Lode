# M2 — Client

## T020 — HTTP client library (`lode-client`)

**Goal:** a typed async client for the whole core API.
**Depends on:** T005. Can start while M1 is in progress (test against a mock until T027).

**Requirements**
- One method per endpoint of ARCHITECTURE §6 using `lode-proto` types; errors decoded into a
  typed `ApiError { code, message, details }` distinct from transport errors.
- Blob upload from an `AsyncRead` with zstd content-encoding; blob download to an `AsyncWrite`
  verifying the BLAKE3 id while streaming and failing on mismatch.
- NDJSON manifest returned as a `Stream`.
- Retries with backoff for idempotent requests and for commits (safe because of `request_id`);
  no retry on 4xx.
- Refuses `http://` to non-loopback hosts unless explicitly allowed. `User-Agent: lode-client/<v>`.
- Credential store: per-server token file in the user config dir with owner-only permissions
  (Unix mode 0600; on Windows rely on the profile directory ACL and say so).

**Acceptance**
- Against a mock server: each error code maps to the right `ApiError`; a 503 then 200 is retried;
  a 409 is not.
- Download with a corrupted body fails verification and leaves no partial output file.
- Plain HTTP to a non-loopback host is refused by default.

**Out of scope:** workspace logic.

## T021 — Workspace database and scanner (`lode-workspace`)

**Goal:** local state and change detection.
**Depends on:** T002. Can start while M1 is in progress.

**Requirements**
- `.lode/` layout and schema per ARCHITECTURE §10.1 with migrations; workspace discovery by
  walking up from the current directory; a workspace lock file so two `lode` processes do not
  mutate the same workspace concurrently (readers such as `status` may run in parallel).
- Scanner per ARCHITECTURE §10.2: honours `.lodeignore` (gitignore syntax, nested files
  supported) and the view; never descends into `.lode/`; parallel hashing; reports
  `unchanged | modified | added | deleted | missing | untracked | conflicted` per path;
  detects executable bit (Unix) and symlinks; handles files changing during the scan by
  re-statting after hashing.
- Local path ↔ `DepotPath` conversion, rejecting local names that are not valid depot paths
  with a clear message instead of failing the scan.
- Text/binary classification per ARCHITECTURE §10.4.
- Blob cache with LRU eviction and a size cap.

**Acceptance**
- Each status is produced for its scenario in a temp directory.
- Touching a file without changing content reports unchanged and refreshes the stored mtime.
- Ignore rules, nested ignore files and view exclusion are honoured.
- A second mutating process fails fast with "workspace is in use".
- Scan of 200,000 unchanged files meets SPEC §10 (ignored-by-default benchmark test).

**Out of scope:** any server communication.

## T027 — Test kit (`lode-testkit`)

**Goal:** make end-to-end tests cheap to write.
**Depends on:** T015, T020.

**Requirements**
- `TestServer::start()` runs `lode-server` in-process on a temp data dir and a free port, with
  a controllable clock, an admin token and helpers to create users, agents, depots and ACLs.
- `TestWorkspace` wrapper that runs the real `lode` binary (`assert_cmd`) with isolated config
  and home directories, plus helpers to write files and parse `--json` output.
- Fault injection hooks: named failpoints in the commit path that tests can arm to abort.

**Acceptance**
- A sample test creates a server, a depot, commits one file through `lode-client`, and reads
  it back. Tests using the kit run in parallel without interfering.

**Out of scope:** the CLI commands themselves.

## T022 — `login`, `checkout`, `view` (`lode-cli`, `lode-workspace`)

**Goal:** get a workspace onto disk.
**Depends on:** T021, T027.

**Requirements**
- CLI skeleton with `clap`: global flags `--json`, `--server`, `-C <dir>`, `--insecure`;
  the exit codes of SPEC §9; human output to stdout, diagnostics to stderr.
- `lode login <url>`: prompts for name and password without echo (or `--token-stdin`), stores
  the token. `lode logout`. `lode whoami`.
- `lode checkout <url>/<depot> [dir]` with `--branch`, `--include`, `--exclude`: creates the
  workspace, fetches the full manifest, downloads blobs in parallel into `.lode/tmp`, verifies,
  renames into place, sets mode bits and symlinks, records rows.
- Safe materialization per ARCHITECTURE §7: no write may escape the workspace root, including
  through pre-existing symlinks.
- Resumable: rerunning after an interruption continues without re-downloading finished files.
- `lode view show|include|exclude`: changes the view and syncs files in or out; refuses to
  drop files with local modifications unless `--force`.
- Progress display on a TTY; silent with `--json`.

**Acceptance**
- Checkout of a seeded depot reproduces contents, executable bits and symlinks (Unix).
- A manifest containing `../x` or an absolute path (served by a fake server) is rejected and
  nothing is written outside the root. A directory replaced by a symlink pointing outside the
  root is not followed.
- Killing checkout midway and rerunning completes with correct contents.
- View include/exclude adds and removes exactly the matching files.

**Out of scope:** update of an existing workspace (T025).

## T023 — `status`, `add`, `rm`, `mv`, `cp`, `revert`, `diff`

**Goal:** local change management.
**Depends on:** T022.

**Requirements**
- `status [paths]`: one line per changed path with a status letter, copy origin, changelist
  and lock markers; `--json` form documented in the command's help.
- `add` (files and directories, recursive, honouring ignores; `--force` to add ignored),
  `rm` (`--keep` leaves the file on disk), `mv` and `cp` recording `copy_from` (with `--after`
  for operations already done on disk; directories supported), `revert` (restores from the
  blob cache or server; for adds just untracks).
- `diff [paths]`: unified diff of text files against base content; binary files reported as
  changed with sizes. `--stat`.
- Choose and record the diff/merge crate (AGENTS.md).
- `revert` requires paths or `--all`; with neither it is a usage error. `revert --all` reverts
  every tracked change and clears conflict state, removing `.theirs-r<N>` files. (Abandoning a
  pending merge is added to it by T051.) A reverted add stays on disk, untracked.
- `lode clean [--ignored] [--dry-run] [paths]`: deletes untracked files and directories left
  empty; ignored files only with `--ignored`; never touches tracked files or `.lode/`; lists
  what it removed.

**Acceptance**
- Each command's effect is visible in `status` and in the workspace database.
- `mv` of a modified file commits later as add-with-copy-from plus delete (verified in T024).
- `revert` restores exact content and mode.
- After arbitrary local damage (modified, added, deleted, missing, untracked and ignored
  files), `revert --all` then `clean` leaves the tree byte-identical to a fresh checkout plus
  ignored files; with `clean --ignored`, identical to a fresh checkout.
- `clean --dry-run` deletes nothing and lists the same paths the real run removes.
- `diff` output applies cleanly with a standard `patch` tool (test on Unix only).

**Out of scope:** commit, changelists.

## T024 — `commit`

**Goal:** send changes to the server.
**Depends on:** T023.

**Requirements**
- Flow per ARCHITECTURE §10.3. Message from `-m`, `-F <file>` or `$EDITOR`; empty message
  aborts. `-A` adds untracked files first. Optional path arguments limit the set.
- Stable `request_id` persisted in the workspace before sending, so a retry after a crash or
  timeout cannot create a second revision.
- Files that change between hashing and upload are detected (re-stat) and abort the commit.
- On `out_of_date`, `locked`, `lock_required`, `permission_denied`: print the affected paths
  and what to do next.
- After success: update rows, print the revision number.

**Acceptance**
- Add/modify/delete/rename round trip: a second workspace checking out sees the same tree,
  and `log` shows copy origin for the rename.
- Only missing blobs are uploaded (assert request counts via the test server).
- Commit with a stale file fails `out_of_date` and changes nothing locally or remotely.
- Simulated timeout after the server committed: retry reports the same revision.

**Out of scope:** changelists (T034), merge metadata (T051).

## T025 — `update`, `resolve`

**Goal:** bring a workspace to a newer revision, merging local changes.
**Depends on:** T024.

**Requirements**
- `lode update [-r REV]` implementing every row of the table in ARCHITECTURE §10.4, with
  three-way text merge and standard conflict markers (`<<<<<<< mine`, `=======`,
  `>>>>>>> theirs r<N>`).
- Resumable and safe on interruption. Updating to an older revision is allowed when there are
  no local modifications in affected files.
- `lode resolve <path> --mine|--theirs|--merged`; conflicted files block `commit`.
- Summary of updated, merged, conflicted, deleted counts; `--json` lists every path and outcome.
- Removes directories that became empty.
- Access epoch (ARCHITECTURE §6, §10.4): store the value from each manifest response; when it
  differs from the stored one, do a full-manifest sync. A tracked file absent from a full
  manifest is removed if unmodified, and kept and reported if modified. Acceptance: after an
  ACL change hides a folder, the next `update` removes its unmodified files.

**Acceptance**
- One test per table row. Clean merge of non-overlapping edits; overlapping edits produce
  markers and `conflicted` state; binary conflict keeps the local file and writes
  `.theirs-r<N>`.
- After `resolve`, commit succeeds and the temporary `.theirs` file is gone.
- Interrupted update rerun converges to the same result as an uninterrupted one.

**Out of scope:** branch switch (T050), merge between branches (T051).

## T026 — `log`, `cat`, `ls`

**Goal:** history inspection.
**Depends on:** T022.

**Requirements**
- `lode log [path] [-n N] [--branch B] [--follow]` showing revision, author, submitter when
  different, time, message, changed paths with `-v`; marks agent authors.
- `lode cat <path>[@rev]` to stdout (binary-safe). `lode ls [path][@rev]` with `-l`.
- All three work without a workspace when `--server` and `--depot` are given.

**Acceptance**
- Output and `--json` forms covered by snapshot tests against a seeded depot.
- `cat` of a binary file is byte-identical.

**Out of scope:** blame (T052).

## T028 — JSON contract, exit codes, external subcommands

**Goal:** make the CLI a dependable machine interface.
**Depends on:** T025, T026.

**Requirements**
- Audit every command: with `--json`, stdout carries exactly one JSON document
  (`{"ok":true,…}` or `{"ok":false,"error":{code,message,details}}`), nothing else; progress
  and prompts suppressed; non-interactive (fails rather than prompts).
- Exit codes per SPEC §9 for every error path.
- Unknown subcommand `foo` runs `lode-foo` from `PATH` if present, passing `LODE_SERVER`,
  `LODE_DEPOT`, `LODE_WORKSPACE` and `LODE_TOKEN_FILE` in the environment (not the token itself).
- Write `docs/CLI-JSON.md` documenting the JSON schema of each command.

**Acceptance**
- A test iterates over all commands in success and failure cases and checks stdout parses as
  one JSON document and the exit code matches the table.
- External subcommand dispatch works and receives the environment.

**Out of scope:** new commands.
