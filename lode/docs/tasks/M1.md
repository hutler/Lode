# M1 — Server core

All tasks here are in `lode-server` (and `loded` for wiring) unless stated.

## T010 — Server skeleton

**Goal:** a running `loded` with configuration, logging, error model and `/info`.
**Depends on:** T003, T004, T005.

**Requirements**
- `loded init <data-dir>` creates the directory layout and database, and writes a commented
  default `loded.toml`. `loded serve --config <file>` runs the server. Graceful shutdown on
  SIGINT/SIGTERM/Ctrl-C, finishing in-flight requests.
- Config: listen address, optional TLS cert/key (rustls), data dir, limits (ARCHITECTURE §6),
  `[modules]` table. Unknown keys are an error.
- One `ApiError` type mapping every `ErrorCode` to its HTTP status and the JSON error body.
  Panics in handlers become `internal` without leaking details.
- Request id per request in logs and in an `X-Request-Id` response header. Structured logging
  with `tracing`.
- Shared `AppState` holding `MetaStore`, `BlobStore`, config, clock.
- `GET /api/v1/info`.

**Acceptance**
- `init` then `serve` on a temp dir answers `/info` with version and an empty module list.
- Unknown route → `not_found` JSON body. Oversized JSON body → `too_large`.
- TLS mode serves HTTPS with a test certificate.
- Refuses to start on a missing or uninitialized data dir with a clear message.

**Out of scope:** auth, any depot endpoint.

## T011 — Authentication

**Goal:** principals, passwords, tokens and scopes.
**Depends on:** T010.

**Requirements**
- `loded init` creates an `admin` user and prints a one-time token with all scopes.
  `loded reset-admin --config <file>` revokes that user's tokens and prints a new one.
- Token format `lode_<base64url of 32 random bytes>`; stored as SHA-256; constant-time compare;
  optional expiry; `last_used_at` updated at most once a minute.
- Axum extractor producing `Caller { principal, scopes, token_id }`; missing or bad token →
  `unauthenticated`; disabled principal → `unauthenticated`.
- `require_scope` helper. Scopes are strings. Core scopes: `read`, `write`, `admin`. Further
  scopes are declared by modules (T017); until then the registry holds only the core set.
  Creating a token with an unknown scope is `invalid_request`; a stored scope that is not
  currently registered is kept and ignored.
- Endpoints: `POST /auth/login` (Argon2id verify, returns a new token; rate-limited per name
  and per address, in memory), `GET /auth/whoami`, `GET/POST/DELETE /tokens` (own tokens; a
  token cannot mint a token with scopes it lacks).
- Admin endpoints for principals and groups: create/list/disable user, create agent (owner
  required), set password, group membership.

**Acceptance**
- Login with right/wrong password; lockout after repeated failures and recovery after the
  window (using the injected clock).
- Expired, deleted and disabled-principal tokens are rejected.
- A `read`-only token cannot create a `write` token.
- The token value never appears in logs or in any response except its creation.

**Out of scope:** OIDC, per-path permissions (T012).

## T012 — Permissions

**Goal:** ACL evaluation and its admin API.
**Depends on:** T011.

**Requirements**
- `Permissions::level(caller, depot, branch, path) -> None|Read|Write|Admin` implementing
  SPEC §5.5 exactly: default none; a matching `deny` at or below the requested level wins;
  otherwise the highest matching `allow`. Subjects: all, user, group. A rule with
  `depot_id NULL` applies to every depot.
- Server admins (scope `admin` plus an `allow admin` rule on a depot, or the built-in `admin`
  user) bypass path rules for that depot.
- Bulk check helper for a list of paths that compiles globs once per request.
- A filter usable by manifest and tree listings to drop unreadable paths efficiently.
- Access epoch (ARCHITECTURE §6): a persisted counter raised in the same transaction as any
  change to ACL rows or group membership, readable by other services.
- Admin endpoints to list, add and remove ACL rows. Rules are cached in memory and reloaded
  on change.

**Acceptance**
- Table-driven tests covering: default deny, allow by user/group/all, deny overriding allow,
  branch-glob and path-glob matching, depot-wide rules, agent not inheriting owner access.
- Bulk check of 100,000 paths against 50 rules completes in well under a second (benchmark
  test with a generous bound).

**Out of scope:** per-path authorization of blob downloads (documented limit).

## T013 — Blob API

**Goal:** upload, download and existence queries.
**Depends on:** T011.

**Requirements**
- `POST /depots/{d}/objects/missing`, `PUT /depots/{d}/blobs/{id}`,
  `GET /depots/{d}/blobs/{id}` per ARCHITECTURE §6. Depot create/list endpoints
  (`POST /depots` admin-only) are part of this task.
- Upload streams the body into `BlobStore::put` (decoding `Content-Encoding: zstd` on the fly);
  requires scope `write` or `shelve`; honours the size limit; returns 201 or 200 (already present).
- Download streams; serves stored zstd bytes directly when the client accepts zstd and the
  object is stored compressed; sets `ETag` to the id and long-lived immutable cache headers.
- Only objects of kind blob are served. Tree objects are never downloadable.
- `objects/missing` needs scope `write` or `shelve`, the same as upload; a `read`-only token
  gets `permission_denied`. Ids of tree objects are always reported as missing.

**Acceptance**
- Upload/download round trip, plain and zstd, including a multi-hundred-megabyte stream with
  bounded server memory.
- Body not matching the id in the URL → `hash_mismatch`, nothing stored.
- Aborted upload leaves no object and no lasting temp file.
- Requesting a tree id via the blob endpoint → `not_found`.

**Out of scope:** range requests on compressed objects, batch download.

## T014 — Commit engine

**Goal:** atomic commits per ARCHITECTURE §5.
**Depends on:** T012, T013.

**Requirements**
- `TreeEditor`: given a root tree id and a validated change set, produce the new root tree,
  loading and writing only the directories on changed paths, removing directories that become
  empty. Tree objects are cached in a bounded in-memory LRU keyed by id.
- `Commits::commit(caller, depot, branch, request, author_override)` implementing every step
  of ARCHITECTURE §5.2 in order, with the stated error codes and `details.paths`.
- Hook points for modules are called but the module list may be empty until T017.
- `commit` takes author and submitter separately (equal for a direct commit) and stores both.
- Branch configuration per ARCHITECTURE §5.2: a commit that adds or modifies `.lodeconfig`
  with unparseable content is rejected `invalid_request` before the transaction; the head
  `.lodeconfig` is parsed once per blob id into a bounded cache and loaded outside the
  transaction on a miss.
- Creating a depot creates branch `main` with revision `r1` (empty tree).
- `POST /depots/{d}/branches/{b}/commits`.

**Acceptance**
- Add, modify, delete, copy-with-history; nested directories created and pruned.
- Property test: applying a random change sequence with `TreeEditor` equals building the tree
  from the final file set.
- `out_of_date` for: modify with stale `base_id`, delete of a changed file, add of an existing
  path. A commit touching other files than a concurrent commit succeeds.
- Missing blob → `missing_objects` listing the ids. Case-insensitive collision → `invalid_path`.
- Same `request_id` twice → same revision, one row.
- No `write` permission on one path → `permission_denied`, nothing written.
- 50 concurrent commits on disjoint files all succeed with distinct consecutive revisions;
  50 concurrent commits to the same file: exactly one succeeds.
- `rev_change` rows match the request, with correct `old_id`.

**Out of scope:** merging on the server, shelves, locks.

## T015 — Read API

**Goal:** everything a client needs to sync and inspect history.
**Depends on:** T014.

**Requirements**
- `Depots` service and endpoints: revisions list (by branch, optionally by path, following
  `copy_from` when `follow=true`), revision detail, `manifest` (full and delta, NDJSON,
  streamed), `tree`, `files`.
- Tree diff walks two root trees and skips identical subtrees by id.
- All listings filtered by read permission and by `include`/`exclude` globs.
- `files` returns raw content with `X-Lode-Id`, kind and executable headers.
- Revision list parameters per ARCHITECTURE §6: `before` (descending), `after` (ascending),
  optional `branch` (depot-wide when absent), `own`, `changes` with a per-revision cap
  (default 1,000 paths) and `changes_truncated`. In a depot-wide list, a revision on a branch
  the caller cannot read at all is omitted; changed paths are filtered by read permission.
- Every manifest response carries `X-Lode-Access-Epoch` (T012).

**Acceptance**
- Full manifest of a 50,000-file tree streams with flat memory.
- Delta manifest between two revisions equals the difference of their full manifests, for
  adds, modifies, deletes, and across branches.
- Unreadable paths never appear in any listing; `files` on one → `not_found` (not 403, to
  avoid revealing existence).
- Log by path follows a rename when asked.
- `after=N` returns exactly the revisions above `N` in ascending order across branches, each
  naming its branch; paging through it with the last number seen misses and repeats nothing
  while commits arrive concurrently.
- `branch=feature&own=true` excludes inherited revisions; without `own` they are included up
  to the branch point.
- `changes=true` returns paths, truncates at the cap with the flag set, and hides unreadable paths.
- The access-epoch header changes after an ACL or group change and not otherwise.

**Out of scope:** blame (T052), search.

## T016 — Branches

**Goal:** create, list, show and archive branches.
**Depends on:** T014.

**Requirements**
- Endpoints per ARCHITECTURE §6 and creation per §5.3. Branch names: `[A-Za-z0-9._/-]`, no
  leading/trailing `/`, max 200 chars, unique per depot case-insensitively.
- Creating needs scope `write` and `write` permission on the new branch name pattern and
  `read` on the source. Archiving needs `admin` on the depot. Commits to an archived branch →
  `branch_archived`.

**Acceptance**
- New branch has one revision whose parent is the source revision and whose tree equals the
  source tree; no objects are copied.
- History queries on the new branch include the source history up to the branch point only.
- Archive blocks commits and hides the branch from the default listing.
- Creating a branch writes `revision.created` and `branch.created`, and archiving writes
  `branch.archived`, to the outbox in the same transaction (payloads per ARCHITECTURE §8.1).

**Out of scope:** client switching (T050), merge (T051).

## T017 — Module framework

**Goal:** the extension points of ARCHITECTURE §8.
**Depends on:** T014.

**Requirements**
- `Module` trait, `ModuleCtx` and the service traits it exposes (`Auth`, `Depots`, `Commits`,
  `Blobs`, `Meta`), registration in `loded` driven by `[modules]` config, route mounting,
  module migrations, `pre_commit` / `in_commit` invocation inside the commit transaction,
  `gc_roots`.
- Outbox dispatcher: after each commit and at startup, deliver events in order to each
  subscriber, advance the cursor after success, retry with backoff on failure without
  blocking other subscribers.
- `/info` lists enabled modules.
- `CommitCtx` per ARCHITECTURE §8: author, submitter, branch, changes, `extensions`, parsed
  branch configuration, head-tree lookup. `Commits` lets a module commit with an author
  different from the caller.
- `ToolDef` and the tool registry per ARCHITECTURE §8: collected from `mcp_tools()` of enabled
  modules, exposed through `ModuleCtx`, each tool declaring the scope it needs.
- `Module::scopes()` and the scope registry per ARCHITECTURE §7–8: scopes of enabled modules
  are accepted at token creation; each `ScopeDef` says whether it is an agent default.
- `CommitCtx.origin` per ARCHITECTURE §8: `Direct` for client requests; `Module {name, attrs}`
  only through `Commits`. No request field can influence it. It is included in the
  `revision.created` event.
- Event envelope and core event payloads per ARCHITECTURE §8.1.
- Outbox pruning per ARCHITECTURE §8: rows passed by every registered subscriber are deleted;
  cursors of unregistered subscribers are dropped.
- A tiny example module under `lode-server/tests` that rejects commits whose message is empty
  and counts delivered events, to prove the surface is sufficient.

**Acceptance**
- The example module can reject a commit with its own error code and message.
- An `in_commit` failure rolls the whole commit back.
- Events are delivered at least once across a server restart (kill between commit and delivery).
- A disabled module contributes no routes, tables, hooks or tools.
- The example module reads its own section of the branch configuration in `pre_commit`
  without any blob access, and sees distinct author and submitter when a commit is made on
  someone's behalf.
- The example module's tool appears in the registry with its declared scope.
- The outbox table is empty after all subscribers have caught up, and a cursor left by a
  module that is now disabled does not prevent pruning.

**Out of scope:** real modules (M3), webhooks.

## T018 — Garbage collection

**Goal:** reclaim unreferenced objects safely while online.
**Depends on:** T017.

**Requirements**
- Mark-and-sweep per ARCHITECTURE §11, including module roots and the grace period.
- Mark uses a memoized walk (visited-set of tree ids) so shared subtrees are visited once.
- `POST /depots/{d}/gc` (admin) with `dry_run`; returns counts and bytes.
- Safe against a commit racing the sweep: an object uploaded during GC is protected by the
  grace period; document the argument in code.

**Acceptance**
- Orphan blobs older than the grace period are removed; younger ones and all referenced
  objects (including via shelves' roots, simulated with the example module) survive.
- GC running concurrently with a stream of commits never breaks `fsck` (T019) afterwards.

**Out of scope:** obliterate.

## T019 — fsck and backup

**Goal:** verify and back up a depot.
**Depends on:** T017.

**Requirements**
- `fsck` per ARCHITECTURE §11, quick and `--full`; reports each problem with revision/path/id;
  non-zero result when anything is wrong. Endpoint plus `loded fsck` offline command.
- `loded backup <dest>` producing a consistent copy per ARCHITECTURE §11.

**Acceptance**
- Clean depot passes. Deleting an object, truncating one, corrupting one byte (`--full`), and
  pointing a branch head at a missing revision are each detected.
- A backup taken during continuous commits passes `fsck` when opened as a data dir.

**Out of scope:** repair.
