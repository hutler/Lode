# M9 — GUI core

A desktop app, Lode Desk, lets someone sign in, check out, see what changed, commit, and read
history and diffs without a terminal, on Windows, macOS and Linux. It runs the same Rust code
as `lode`, so the two never disagree. Plan: "Lode after v1" (2026-11-14); decisions: Tauri 2
with React and TypeScript, in this repository as `crates/lode-desk`, unsigned for 0.x, working
name "Lode Desk".

## T090 — `lode-ops` library

**Goal:** one implementation of every client operation, used by the CLI and the GUI.
**Depends on:** T087.
**Scope:** new crate `lode-ops`, `lode-cli`, docs.

**Requirements**
- The command logic of `lode-cli` (context, sign-in resolution, workspace helpers, and every
  command except `mcp`, `self-update` and external subcommands) moves into `lode-ops`.
- An operation takes its options and returns the same JSON document that `lode <cmd> --json`
  prints (`docs/CLI-JSON.md` stays the one contract), or an error with the same `code`,
  `message`, `details` and exit class.
- Human lines, warnings and progress go through a `Reporter` trait instead of the terminal.
  The CLI's reporter prints exactly what it prints today; a GUI reporter turns them into
  events.
- Nothing in `lode-ops` reads standard input, starts an editor or asks a question. The CLI
  resolves prompts (password, commit message editor, shelve confirmation) before it calls the
  operation, and the operation takes the answer as an option.
- `lode-cli` keeps argument parsing, prompts, the terminal reporter, `mcp`, `self-update` and
  external subcommands.

**Acceptance**
- Every existing CLI test and snapshot passes unchanged.
- A test drives `status`, `commit` and `log` through `lode-ops` with a collecting reporter,
  without the `lode` binary, and gets the documented JSON and the progress events.
- `lode-ops` has no dependency on terminal crates (`rpassword`) and no `stdin` use (checked by
  a test that greps its sources).

**Out of scope:** changing any command's behaviour or output.

## T091 — App shell, sign-in, open and check out

**Goal:** the app starts, signs in, and opens or checks out a workspace.
**Depends on:** T090.
**Scope:** new `crates/lode-desk` (Tauri 2 Rust side) and `crates/lode-desk/ui` (React,
TypeScript, Vite).

**Requirements**
- `lode-desk` is its own Cargo workspace next to the main one (it links `lode-ops` by path),
  so building and testing the CLI and server never needs the system web view libraries.
- Tauri commands wrap `lode-ops` operations one to one and return their JSON; reporter events
  are forwarded as Tauri events. An operation holds the workspace only while it runs, so the
  CLI and editor plugins can work next to the app.
- Screens: a welcome page with recent workspaces, "Open folder", "Check out" (server, depot,
  branch, target folder) and "Sign in" (server, name, password; uses `lode login`'s stored
  credentials, so a CLI sign-in counts too).
- Open workspaces appear as tabs. A sidebar shows the branch, revision and server.
- Errors show the operation's `message` and, where the CLI has one, its advice.
- The UI follows the system light or dark theme.

**Acceptance**
- Rust tests run each wrapped command against a test server.
- UI tests (Vitest and Testing Library) cover sign-in, check out and the error display
  against a mocked backend.
- A browser screenshot run renders each screen against the mocked backend in light and dark
  (Playwright), and the images are kept as build artifacts for visual review.
- The app builds and starts on Windows and Linux (manual on the PC; Linux in CI).

**Out of scope:** installers and auto-update (T114), `lode://` links (T113).

## T092 — Pending changes and commit

**Goal:** daily work: see changes, pick files, commit.
**Depends on:** T091.
**Scope:** `lode-desk`.

**Requirements**
- The pending-changes view lists `status` results grouped by changelist, with the status
  letter as an icon, the lock marker, "needs lock", and the copy or move origin.
- Checkboxes pick the files to commit; a commit box takes the message; Commit runs `commit`
  with the picked paths and shows upload progress.
- Revert (with a confirmation) and "Add" for untracked files from a right-click menu.
- The view refreshes when files in the workspace change (file watcher, debounced), and on
  focus.
- A refused commit (out of date, needs lock, submit gate) shows the reason and the next step.

**Acceptance**
- UI tests for grouping, selection and the refused-commit display; a Rust test that the
  watcher triggers one refresh for a burst of changes.

**Out of scope:** moving files between changelists (T101).

## T093 — History, file history and blame

**Goal:** read what happened and who did it.
**Depends on:** T091.
**Scope:** `lode-desk`, `lode-ops` if `log` needs paging.

**Requirements**
- History view: the branch's revisions, newest first, with merges drawn as a graph, author,
  date, message, an agent badge for agent provenance and "imported from git" for imports.
  Long histories load in pages and scroll smoothly (virtual list).
- Selecting a revision shows its changed files; selecting a file shows its diff (T094).
- File history and blame for one file, from the pending view or the revision view.

**Acceptance**
- UI tests for the graph layout of a branch with two merges and for paging; the screenshot
  run covers the history and blame views.

**Out of scope:** check results per revision (T103).

## T094 — Text diff

**Goal:** read changes the way people expect from a desktop version control client.
**Depends on:** T092, T093.
**Scope:** `lode-desk`.

**Requirements**
- Unified and side-by-side diff of a working file against its base, and between two
  revisions, with line numbers and word-level highlights inside changed lines.
- Binary files show their size and kind instead of a diff (image diff is T104).
- Large files fall back to plain text above a size limit and say so.

**Acceptance**
- UI tests for both layouts, word highlights and the binary case; screenshots in the run.

**Out of scope:** syntax highlighting by language, editing in the diff view.
